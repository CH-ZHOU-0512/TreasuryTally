# M12 财务运营首次上手交接

## 分支与边界

- 分支：`codex/m12-user-experience`
- 基线：`f66b5ad`
- 写入范围：`app/`、`tests/m12/`、本文件。
- 未修改领域模型、Schema、M9/M10 工作区或根目录权威文档。

## 已实现

- 上传区可在“上传自己的 JSON”和“加载契约测试示例”之间选择；示例来自既有 M1 人工标注合成 fixture，并在页面明确标为非 M11 真实案例。
- 提供可直接通过现有 `UploadedReport` 校验的严格 JSON 空白模板下载，不把 JSON Schema 冒充填写模板。
- 结果区新增精确金额方向说明，继续以整数最小单位计算；有 decimals 时仅做确定性字符串格式化，不经过 `float`。
- Finding 改为中文业务原因与处理建议，并可逐项展开规则、预期、实际和完整证据引用；原资金流事件详情与真实 Sepolia 交易入口保持不变。
- 新增 M12 专属测试，覆盖模板/示例契约、金额方向、证据不足和 Finding 文案完整性。

## 集成交接

- A 提供 M11 案例后，由集成负责人把示例来源从现有合成 fixture 接到冻结后的案例 manifest；本分支未假装已有真实案例，也未跨工作区复制文件。
- 当前 `AppRuntime` 没有公开案例 manifest 端口，因此示例加载暂时只在页面适配层读取既有 fixture。若公共 wiring 要支持多案例，建议由集成负责人提供只读案例选择端口，不改变 `UploadedReport`。
- M12 没有改范围候选契约；示例仍须走现有候选确认和任务锁定，不能绕过确认。
- 页面默认保留“上传自己的 JSON”，范围字段可编辑，运行配置保留“真实 Sepolia RPC”；固定样例只是辅助入口，
  不是完成主流程的唯一方式。
- 本轮没有真实用户或测试用户参与，未做招募、访谈或人工可用性测试；下述自动化与浏览器证据只证明支持范围内的
  技术可操作性，不等于真实用户验证。
